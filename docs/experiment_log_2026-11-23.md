## 2. 현재 문제점

1. **specialist가 VLA를 넘지 못합니다.**
   - critic은 상태의 가치는 잘 맞힙니다 (실제 return과 상관 0.96~0.98). 하지만 같은 상태에서 residual을 바꿨을 때의 Q 차이는 상태 간 차이의 1/100~1/175입니다. 즉 어떤 residual이 좋은지 구분하지 못합니다.
   - 그래서 actor가 근거 없이 움직이고, 체크포인트마다 성능이 크게 출렁입니다 (c2: 0.16~0.60).
   - 우리 specialist는 24~58%입니다. 논문은 데이터를 모을 때의 specialist 성공률 기준을 밝히지 않았지만, 다음과 같이 보고합니다.
     - 서론: "specialist가 임의의 상태에서 이어받아 99% 이상 성공"
     - §4.1: "fine-tuning 결과를 보고한 120개 이상 작업 모두에서 95% 이상"
     - 실제 로봇: "두 작업에서 100%에 도달한 뒤 성공 시연 200개를 수집"
2. **ξ를 키우면 회복하지 못합니다.** ξ 0.3과 0.5는 250k step 동안 논문과 같은 "하락 후 회복"이 없었고, 최종 평가는 0/50이었습니다.
3. **residual이 개입하는 시점에 따라 효과가 다릅니다.**
   - VLA가 막혀 있는 중반(160~320 step)에 넘겨받으면 VLA보다 낫습니다 (약 0.46 vs 0.19~0.33).
   - VLA가 잘하던 초반에 넘겨받으면 망칩니다 (0.70 → 0.54).
4. **PLD 데이터의 질.** 데이터의 절반이 약한 specialist의 action이라, 잡음이 섞였을 가능성이 있습니다. SFT 50에서 고정 주방 성공률이 떨어진 원인으로 의심합니다. self-bootstrap 비교로 확인할 예정입니다.
5. **평가 검정력이 부족합니다.** 50 에피소드면 오차가 ±7%p라서, 지금까지의 SFT 차이는 모두 통계적으로 유의하지 않습니다.
6. **bw2 환경 멈춤.** 실행 두 개를 환경 32개씩 동시에 돌리자 환경 프로세스가 CPU 100%로 멈췄습니다 (3회). 감시 기능(멈춘 프로세스 교체)을 넣고, 실행당 환경을 16개로 제한한 뒤로는 재발하지 않았습니다.
7. **논문과 다른 점**
   - 옵션 B critic (논문 Eq.2와 다름)
   - 카메라 3대, 256 px, augmentation, 회전 ξ 축소
   - α: Stage 1은 0.8, Stage 2는 0.6
   - XR-1 LoRA 학습기는 직접 구현했고, 공식 기본값은 전체 fine-tuning용이라 학습률을 1e-4로 올림
   - 참고: Stage 2에서 residual이 개입한 성공만 저장하는 것은 논문의 PLD 데이터 정의(§3.2 τ_demo, Algorithm 1)를 따른 것입니다. VLA가 T_base 전에 혼자 성공한 에피소드는 논문의 self-bootstrap 데이터(D^Base Policy)에 해당하므로 제외했습니다.
8. **바로잡은 실수**
   - 논문의 α 결과를 "0.6에서 정체"로 잘못 전달했습니다. 실제로는 0.6 이후 하락합니다.
   - SFT 손실을 micro-batch 하나 값으로 기록하고 있었습니다 (수정함).
   - Stage 1 중간 체크포인트를 남기지 않았습니다 (수정함).
   - offline 수집 성공률을 기준선으로 쓰면 성공 쪽으로 치우칩니다 (수정함).
9. **평가 해석**
   - 고정 주방 = 논문의 benchmark 실험 (LIBERO처럼 작업과 장면은 같고, 배치만 다름)
   - 처음 보는 주방 = RoboCasa365 공식 split이자, 우리 설정에서는 OOD (논문의 실제 로봇 Table 6과 비슷)
